# CakeGame

> 2D 俯视像素动作对战。1~3 名真人对抗 1~2 个算法极强 AI Bot。没有专用服务器，没有大厅服务器，也没有简单模式。

[English](README.md) · [落地页](index.html) · [许可证](LICENSE)

---

## 这是什么

CakeGame 是用 **Godot 4.5.1** 做的**俯视视角像素动作对战游戏**。1~3 名真人组队对抗 1~2 个 AI Bot，可以在单机上直接开打，也能通过局域网／公网房间码拉人进来。

有一条贯穿全局的设计原则：**Bot 的难度恒定，不可调节**。因为难度滑条的本质是"故意交付一个更弱的 Bot"，而那不是陪练该有的样子。Bot 会预判你的走位、躲开你将要开出的那一枪、把墙角当掩体、并且根据你的状态在枪械与近战之间切换。

---

## 快速开始

**直接玩出品构建。** 把 `CakeGame.exe` 丢到任意目录双击即可 —— 资源已经打包进单个可执行文件，不需要在旁边再放 `project.pck`。

**自己编译。** 需要 Godot 4.5.1 编辑器及对应导出模板，然后：

```bash
godot --headless --path . --export-release "Windows Desktop" build/CakeGame.exe
```

`export_presets.cfg` 里的预设已开启内嵌资源包、注入图标并写入 Windows 版本资源。想让导出日志直接打在控制台上，请改用编辑器的 **console 版**（`Godot_v4.5.1-stable_win64_console.exe`）。

## 操作

角色**永远朝向你的准星来源**：用鼠标时就是指针，用手柄时就是右摇杆。移动与瞄准完全解耦，这也是翻滚能读作"技术"而不是"手滑"的原因。

| 动作 | 键鼠 | 手柄 |
| --- | --- | --- |
| 移动 | `W` `A` `S` `D`（方向键同样可用） | 左摇杆 / 十字键 |
| 瞄准 | 鼠标指针 | 右摇杆 |
| 近战 | **鼠标右键** | `LB` |
| 拔枪 / 收枪 | `E` | `X` |
| 开火 | **鼠标左键**（需已拔枪） | `RB` |
| 抓钩 | `Q` | `Y` |
| 翻滚（无敌帧） | `Shift` | `B` |
| 换弹 | `R` | 左摇杆 |
| 暂停 | `Esc` | `Start` |

除鼠标外的所有按键都能在设置里实时改键；如果新键会与另一个动作冲突，游戏会直接拒绝这次改键。

## 战斗

所有数值集中在 `src/core/balance.gd` —— 一个文件，没有散落的魔法数字。距离一律以 **1 格 = 16 px = 1 米** 书写，并附带 m/s 换算注释，方便心算校验。

| 系统 | 数值 |
| --- | --- |
| 生命 | 100 HP，碰撞半径 5 px |
| 移动 | 57.6 px/s（3.6 m/s），加速度 480，摩擦 560 |
| 近战 | 22 伤害，24 px 触及，±0.95 弧度扇形，共 0.38 s，冷却 0.55 s，击退 150 |
| 枪械 | 12 伤害，弹速 320 px/s，射程 200 px，12 发弹匣，换弹 1.4 s，冷却 0.22 s，每发扩散 3° |
| 抓钩 | 8 伤害，钩速 520 px/s，最大 116 px，冷却 3.2 s，拉力 1200 px/s²，松手保留 62% 速度 |
| 翻滚 | 132 px/s 持续 0.42 s，其中 0.30 s 无敌，冷却 0.90 s |
| 手感 | 顿帧 0.075 s（近战）／0.03 s（子弹）／0.16 s（击杀） |

抓钩是这套移动系统的动词：它既把你拽向墙，又在松手时保留动量，所以同一个键既是越障、又是脱身、也是贴脸。

## Bot

内置两个 Bot，在「设置 → Bot 版本」里切换。

老兵 **`CakeGame AI Bot v1`**（`cakegame_v1`）仍是默认值。它每 0.06 s 重规划一次，但反应延迟是 0.12 s —— 刻意做到超人，绝不做到瞬发。

- **预判射击。** 按子弹速度提前量，并叠加目标加速度的二阶项，所以你"停下来的位置"不会骗到它。
- **预判翻滚。** 判断你是否在瞄它（0.22 rad 锥角），以 0.10 s 反应时间翻滚。
- **距离控制。** 维持 58~92 px 的偏好交战带，20 px 内切近战，血量低于 30 就脱离。
- **掩体与寻路。** 对着墙角僵持 0.7 s 后主动脱离，A* 每 0.32 s 刷新，连续 3 次 1.5 s 无进展会自己脱困。
- **追猎。** 丢失视野后仍沿预判外推 3.5 s 才转去扫另一侧，而不是绕着尸体转圈。

**`CakeGame AI Bot v1 pro`**（`cakegame_v1_pro`）感官与 v1 完全一致，改的是它拿这些信息做什么。完整论证在 `Planning/AI-Bot-v1-Pro.md`，核心其实只有一段算术：

> 在 v1 自己维持的 58~92 px 交战带里，目标张角 4.6°，枪口锥角 3~6°。哪怕散布拉满，对一个**不会动**的目标命中率也有 ~77% —— 所以**"更准"根本不是剩下的空间**。真正吃掉交换的是：一个以 57.6 px/s 移动的目标，在 0.28 s 的飞行时间里能走 16 px，那是它自己轮廓的 2.2 倍。`P(命中) = P(几何) × P(他没有因为你而改变轨迹)`，主导的是第二项。

于是 v1 pro 的选择是**把子弹攒在刀刃上**：在对方物理上躲不掉的时候才开火，其余时间在走位。而这些窗口全部可从动画读出，没有一个是靠读隐藏数据得到的。

- **承诺窗口。** 被锁住的目标（翻滚中、翻滚结束后 0.90 s 冷却里、挥刀僵直中、抓钩眩晕中）集中火力，其余时间用于站位。
- **翻滚计算落点。** 一次翻滚位移约 45 px，所以"落在哪"是被挑选过的 —— v1 完全可能花掉自己 1.32 s 的翻滚锁定，结果落在同一条走廊的另一个位置。
- **开火纪律。** 一个几何命中概率闸门把远距离扫射换成走位逼近，所以它用更少的子弹打出更多伤害。
- **会处理近战。** 近战 22 点是全场最大的单次伤害来源，而 v1 从来不会在被挥砍时脱离弧线；同时它也不再对着"能一滚就走"的目标交出自己的 0.38 s 僵直。
- **多威胁走位。** v1 的移动只看一个目标；v1 pro 会给站位打分，把所有瞄着它的对手一起算进去。
- **抓钩连招。** 对锁定目标必中：8 点伤害 + 0.22 s 硬直 → 贴脸 → 挥刀。另外会往墙上钩来自救脱战，位移约 90 px，是翻滚（45 px）的两倍。

### 靠测，不靠说

`tests/bot_duel.tscn` 跑无头 1v1：24 张地图 × 交换两侧，避免哪一方独占一个半场；阵亡后直接在交火距离内复活：

```
godot --headless --path . --fixed-fps 60 res://tests/bot_duel.tscn

48 duels  (17 decided, 31 draws)
cakegame_v1         5-12-31   win 10.4 pct (all)  win 29.4 pct (decided)
                    K/D 0.61   out-damaged opponent in 14.6 pct of duels
                    damage 3184   shots 797   damage per shot 33.3 of 12
cakegame_v1_pro    12-5-31   win 25.0 pct (all)  win 70.6 pct (decided)
                    K/D 1.64   out-damaged opponent in 37.5 pct of duels
                    damage 3604   shots 756   damage per shot 39.7 of 12
```

三个读数：
1. **子弹更少，伤害更多。** 756 : 797 发，换 +13% 伤害。闸门正是这么设计的——本来要打空的那些子弹，现在用来走位了。
2. **每发伤害高 19%**（39.7% : 33.3%，分母是单发标称 12）。两边都免不了被墙角吃掉的子弹，所以这个数是最干净的"有没有停止浪费子弹"的度量。
3. **决胜局 12-5**，K/D 1.64 : 0.61。多数对决是 0-0，因为两个靠谱的 Bot 很难在 40 s 内杀死对方，所以单看胜场噪声很大——这也是为什么要同时统计伤害。

两条方法学备注，因为"悄悄骗人的基准"比"没有基准"更糟：
- 脚手架**锁死全局 RNG**（`seed(20261001)`）。`ActorBody.fire_bullet()` 用的是全局 `randf_range` 而不是每个大脑自己的 RNG，所以同样代码两次跑出来是 12-2 和 6-6。现在能逐字节复现。
- 它**每帧**从两个大脑**外部**采样交战状态（双方是否有视线、平均距离）。早期有一组配置跑出一串 0 伤害 0 开枪的 0-0，没有这一列的话，"他们根本没碰上"和"他们打了平手"长得一模一样。

Bot 列表是**数据表而不是代码**。想加一个 `CakeGame AI Bot v2`，只要在 `src/ai/` 下丢一个脚本，再往 `BotRegistry.ENTRIES` 里加一条字典 —— 设置里的下拉框直接读这张表，UI 一行都不用改。

## 赛制

三场景路由，带淡入淡出：**主菜单 → 大厅 → 对局**。

一场比赛是**团队积分赛，先到 5 分**（可在设置里改成 1~30）。每回合 3 s 倒计时，结束后 3.4 s 慢镜，存活方得分。重生默认关闭：= **最后一方站着的赢下回合**。想在设置里打开重生就是一场不停歇的乱斗。

摄像机是 `CameraRig`，动态框住**所有**角色并自动缩放去适配，最小取景范围钳在 200×112.5 px，避免只剩一个人时视野被拉得荒腔走板。

## 地图

- **内置竞技场**（默认）：手工设计，34×34 格，视线关系可预期。
- **种子地图**：用你输入的种子生成 56×56 程序化竞技场，种子框留空则随机。种子**在本次会话内锁存** —— 改一次种子框就自动失效，所以重新开一局时不会出现"你以为要新的、其实还是那张图"的情况。

## 联机

**Listen Server。** 谁开的房间谁是主机和权威。Bot **只在主机上模拟** —— 这正是 3 打 2 的对局不用把每个 Bot 的大脑都推给每个客户端的原因。

三级传输按顺序尝试，而玩法层的 RPC 代码完全不需要知道当前用的是哪一级：

1. **局域网** —— 在 `server_port - 1` 上做 UDP 广播发现主机，再在 `server_port` 上直连 ENet。大厅里点 **SCAN LAN**，主机会回一句房间码。
2. **P2P** —— 经信令交换公网端点，然后双方绑定**同一个** UDP 端口互相拨号，让 ENet 自己发出去的数据包去开洞。
3. **中继** —— WebSocket 兜底，打洞不通时使用（对称型／运营商级 NAT、公司代理）。

在设置里选传输偏好（`auto` / `lan` / `p2p` / `relay`）。`auto` 先打洞、失败再中继。大厅里 **HOST P2P** 会把房间发布出去；对端拿到房间码后 JOIN 就能读出主机的端点。

强制两端都绑到 `server_port` 是刻意为之 —— `ENetMultiplayerPeer.create_client()` 默认随机本地端口，而打洞能否命中，取决于 ENet 实际发包的那条 NAT 映射是不是对方敲的那条。

信令与中继地址可在设置里改：

```
signaling_url = https://cakegame.rth1.xyz/api.php
relay_url     = wss://cakegame.rth1.xyz/relay.node.js
```

### 自建后端

[`server/`](server/) 是一份完整而轻量的部署件：

| 文件 | 职责 |
| --- | --- |
| `api.php` | 信令。响应 `ping`、`whereami`、`announce`、`peers`、`leave`。房间是平台 KV 里的 `room:<房间码>:<端点>`，闲置一小时会被清理。 |
| `relay.node.js` | WebSocket 兜底。把二进制帧转发给同房间的其他成员，把房间表镜像进 KV，也能用 `node relay.node.js 8080` 单机跑。 |

把两个文件丢到 PHP 空间 + Node 端点上（Retinbox 就是把它们当 `api.php` 和 `relay.node.js` 服务的），再把地址粘进设置 —— 或者直接改 `src/core/game_config.gd` 里的默认值。其余什么都不用动：客户端会探测这两个端点并自动降级。

`api.php` 在环境里没有 KV 类时，会退化成同级目录下一个 flock 保护的 JSON 文件 —— 这正是协议测试能在任意主机上跑起来的原因。

## 设置

全部持久化到 `user://settings.cfg`。

| 分组 | 选项 |
| --- | --- |
| 对局 | Bot 版本、种子地图 + 种子、人数上限（2~8）、真人槽位、Bot 槽位、目标分数、友伤、重生 + 重生延迟 |
| 手感 | 鼠标灵敏度、手柄瞄准辅助 |
| 表现 | 深色／浅色主题、全屏、窗口缩放 1~4×、主音量／音效／音乐、轻阴影、屏幕震动、伤害数字、FPS 显示 |
| 网络 | 玩家名、端口、上次主机 IP、上次房间码、信令地址、中继地址、传输偏好 |

每个字段在载入时都会做钳制，所以手改过的配置文件不会把你送进一场没法玩的对局。

## 目录结构

```
project.godot            设计分辨率 640x360、expand 拉伸、GL Compatibility
export_presets.cfg       Windows Desktop 预设（内嵌资源包、图标、版本资源）
build/                   导出的 CakeGame.exe（已 gitignore）
assets/                  图标、字体、程序化精灵、音效
scenes/                  main_menu.tscn · lobby.tscn · game.tscn
src/
  core/         枚举、数值表、事件总线、配置、运行时 InputMap、场景路由、音频
  actors/       角色本体与状态机、玩家、Bot、战斗、子弹、抓钩、特效
  states/       共享角色状态
  ai/           BotBrain 基类、注册表、cakegame_v1、cakegame_v1_pro
  world/        场地、瓦片集构建、种子地图生成、摄像机机架
  ui/           像素主题、主菜单、设置、大厅、HUD、暂停菜单、对局根节点
server/         可部署的信令（api.php）与中继（relay.node.js）
tests/          无头测试：selfcheck、match_sim、ui_smoke
promo/          index.html 用到的截图
```

**美术与音频是构建期生成的，不是手绘文件。** 精灵、瓦片和音效都来自 `src/data/atlas_library.gd` 与 `AudioDirector`，这就是为什么整个游戏是一个 97 MB 的单文件，而不是一堆贴图目录。

## 验证

三套无头测试直接在 Godot 引擎里跑，不需要外部测试框架：

```bash
godot --headless --path . res://tests/selfcheck.tscn     # 107 条断言
godot --headless --path . res://tests/match_sim.tscn     #  92 条断言
godot --headless --path . res://tests/ui_smoke.tscn      #  93 条断言
```

注意调用方式：测试套件是**场景**而不是脚本，因为 `--script` 不会把自动加载单例拉起来，三个套件会全部编译失败。

两个后端也各有自己的无头检查：`api.php` 在 `php -S` 下跑完一整轮 ping → whereami → announce × 2 → peers → leave（包括两条必须被拒绝的输入：不足 4 位的房间码、以及不是 `ip:port` 格式的 addr）；`relay.node.js` 由一个双连接测试覆盖 —— 断言二进制帧逐字节送达对端、发送方收不到自己的回环、以及另一个房间完全听不到动静。

`tests/harness.gd` 会给每条检查前后各数一次断言数。中途报错的检查依然会触发计数，所以"0 失败"意味着工作真的跑过了。UI 冒烟套件会在**深色和浅色两套主题**下，把每个面板都量一遍 640×360 设计空间：控件不许出屏、不许互相重叠、文字与自身背景的对比度不低于 0.5。

## 导出 Windows 可执行文件

`tools/build_exe.bat` 一条龙完成 Windows 全流程：自动定位 Godot（会尝试多个候选路径，因为裸 `godot` 经常不在 `PATH` 里），导出 release 到 `build/`，并回报结果。

想验证的是打包体而不是编辑器，可以这样：

```bash
./build/CakeGame.exe --write-movie frame.png --fixed-fps 30 --quit-after 40
```

它会录下 40 帧真实渲染画面然后退出 —— 黑屏或场景缺失会立刻表现为"少了一堆帧文件"，而不是"看着像启动成功了"。
